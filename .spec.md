# 📋 Contrato SHDD: Integración de Remotion como Motor de Video (ISS-040)

### 🎯 Target Files Permitidos
Lista blanca estricta de archivos que el sub-agente tiene permiso de modificar o crear:
- [NEW] `src/core/remotion_engine.py`
- [MODIFY] `src/ui/tab_media.py`
- [NEW] `test/test_remotion_engine.py`

### 🚫 Acciones Prohibidas (Guardrails)
- **NO instalar dependencias nuevas de Python** (usar módulo estándar `subprocess`, `json`, `os`, `pathlib`).
- **NO modificar la lógica actual de corte FFmpeg** en `tab_media.py` (botones de extraer audio o subtítulos). Solo agregar la nueva sección "Motor de Renderizado IA (Remotion)".
- **NO inicializar el proyecto React/Remotion**. El sub-agente solo desarrollará el conector en Python (`remotion_engine.py`).

### 🛠 Instrucciones de Implementación

1. **`src/core/remotion_engine.py`**:
   - Crear una clase `RemotionEngine`.
   - Método `export_props(self, data: dict, dest_path: str) -> str`: Guarda el diccionario recibido en un archivo JSON en la ruta indicada. Debe crear directorios padre si no existen.
   - Método `render_video(self, props_path: str, output_path: str, project_dir: str = "./remotion") -> dict`: Ejecuta mediante `subprocess.run` el comando `npx remotion render src/index.ts MiVideo "{output_path}" --props="{props_path}"` con `cwd=project_dir` (usar `shell=True` en Windows para `npx`). Capturar `stdout`/`stderr` (`capture_output=True`) y si el returncode no es 0, levantar `RuntimeError` con el stderr. Devolver un dict con la metadata (ej: `{"path": output_path, "status": "success"}`).

2. **`src/ui/tab_media.py`**:
   - Importar `RemotionEngine` desde `src.core.remotion_engine`.
   - Agregar una nueva sección debajo del bloque de exportaciones (opcionalmente antes o después del bloque "Exportados en esta sesión") llamada `<p class="step-section-title">Motor de Renderizado IA (Remotion)</p>`.
   - Agregar un botón `btn_render_remotion = st.button("Renderizar Video Completo (Remotion)", type="primary")`.
   - Si se presiona `btn_render_remotion`:
     - Armar un dict `props_data` recolectando cosas de `st.session_state` (por ejemplo: `project_name` y un flag `is_remotion: True`).
     - Instanciar `RemotionEngine`.
     - Definir ruta del JSON: `props_path = OUTPUT_DIR / st.session_state.get("project_name", "test") / "props.json"`. Crear carpeta si no existe.
     - Definir ruta del output: `out_path = OUTPUT_DIR / st.session_state.get("project_name", "test") / "remotion_render.mp4"`.
     - Llamar a `export_props` y luego a `render_video`. (Nota: envolver en un bloque `with st.spinner("Renderizando video en Node.js..."):` y un `try/except` que haga `st.error` si falla).
     - Al finalizar exitosamente, hacer `st.success` y opcionalmente insertar el diccionario con info del clip en `st.session_state["exported_media"]`.

3. **`test/test_remotion_engine.py`**:
   - Escribir tests unitarios usando `unittest.mock.patch` sobre `subprocess.run` para validar que el comando `npx remotion render` se ensambla y llama correctamente sin ejecutar Node.js en CI, y otro test validando que lanza error si `returncode != 0`.
